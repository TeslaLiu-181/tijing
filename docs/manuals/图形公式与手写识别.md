# 图形公式与手写识别

> 本文为保留的功能说明，已清理原部署标识。当前版本、安装步骤和导出差异以根目录 README、PROVENANCE.json 及公开部署指南为准；历史验收记录不是本次交付重新执行的结果。

## 图形编辑与实际应用

图形编辑器使用本地打包的 MathLive 0.111.0（MIT），字体内嵌，不依赖 CDN。点分式、根式、上下标或矩阵后，直接点击二维槽位编辑；方向键移动，Tab 跳到下一个空位。矩阵提供增加/删除行列。LaTeX 源可展开校正，但不是唯一编辑方式。

- 场景参数的“图形编辑依赖”将公式转换为原生表达式，显示实际将应用的表达式。必须先确认变量绑定、量纲与目标，原生依赖验证通过后才写入场景。
- 对象“图形编辑标注公式”保存排版公式；独立标注还可调整字号、宽高或拖动尺寸手柄。排版不改变物理条件。
- 题干、解析、任务正文等数学编辑工具中的“图形编辑”替换光标所在公式，保留前后 Markdown；该文字修改仍按原页面保存。

变量引用保留稳定对象 ID，例如 `o3.value`，不会把当前 8 替换成固定常量。依赖保持开启时，参数 8 改成 12 会重新计算下游。多个对象使用同一符号时，必须明确选择实际引用。“插入具体对象与属性”的可用量会显示单位，例如质量 `[u]`、磁感应强度 `[mT]`、速率 `[10⁵ m/s]`。名称相同的整个磁场 `B` 与其磁感应强度 `B.B` 是不同引用；标量算术中不能把整个几何对象当物理数值。此时编辑器要求选择具体属性，显式选择会覆盖自动同名引用。几何对象仍可用于 `pos`、`area` 等构造/测量函数。等式需确认左侧对应所选目标，随后只应用右侧。

`area(object)`、`perimeter(object)` 可进入依赖表达式；几何测量属性可作为别的对象的输入，是否允许目标写入仍由原生引擎判定。正体单位（如 `\mathrm{cm}`）可转换为单位；斜体 `m`、`T` 等按变量处理，不能从字形猜测物理含义。

积分、求和、一般矩阵、多行推导等可以用于排版，但当前不能直接当作可执行依赖。只有用户明确选择的 2 行 1 列矩阵可以转换为二维 `point(x,y)`。转换模块只转换结构，不执行求解，也不宣称公式一定符合题意。

## 手写公式

联网网页的图形编辑器可打开手写画布。支持鼠标、触摸或笔、橡皮、撤销与重做。先写一条公式，再确认发送范围与模型服务，才创建普通 AI 识别任务。

只发送从实际笔迹裁剪出的本人 PNG，不自动附带当前题图、场景或个人文档。任务上下文 ID 仅用于权限和教师 AI 策略。识别使用当前账号已配置的视觉模型，按现有队列、额度、取消与私有来源机制处理。

结果先呈现候选公式、模型原始识别的变量及歧义。点“图形校正候选”可直接修改分式、下标和符号；独立校正窗口保留本次实际发送的墨迹图片对照，不含再次识别入口，也不再调用模型。LaTeX 源折叠为可选工具，用户不必写代码才能校正。

图形确认返回后，候选与预览更新，旧歧义与总确认勾选清除，必须再次逐项对照原笔迹。原变量表仍表示模型原始识别，不会偷偷把改后的符号绑定到物理对象；返回数据明确标记 `variablesSource: model-original`。再次确认后才返回原来的图形编辑器，并需通过原生检查才实际写入文字或依赖。取消校正保持原候选，简单关闭重开保留本账号当前校正草稿；草稿不会改写服务器原始识别记录。识别不自动求解、不评分，也不属于物理验证。

学生的教师任务若设为“仅提示”或“作业内禁用 AI”，服务端会禁止此自动识别任务；普通本地图形编辑仍可使用。该规则不能阻止学生使用站外工具。离线导出保留图形编辑与内嵌字体，不提供服务器手写识别。

普通关闭重开会等待并恢复同一次已确认的识别请求，避免重复提交；退出或切换身份清除笔迹、图片与结果，并丢弃旧异步回包。关闭窗口不等于取消服务器请求，需点击“取消识别请求”。

## 验收证据与范围

- 定向转换与解析测试涵盖持续依赖、单位、变量歧义、矩阵和 unsafe LaTeX，不用模型。
- 真浏览器 MathLive 验收覆盖分子/分母位置、上下标、矩阵四个单元格与行编辑；不把文本插入按钮当作图形编辑完成。
- 集成合成服务实际确认 `radius=L/2`，参数 8→12 导致原生半径 4→6；标注 `x+1` 真正显示在画布，尺寸手柄改变宽高而源公式不变。
- 实际 PNG 经 iframe 桥进入标准 `formula` job 并回到同一图形编辑器，该 UI 夹具使用本机 mock provider，只证明真实界面/API/确认链路。另有两张纯合成实际笔迹经外部视觉模型识别的独立报告：分式结构转录正确，另一张的字母 o/数字0、theta/Theta 保留歧义。因此必须提供图形校正并由用户对照确认；两例不构成准确率样本集，也不保证所有手写风格或公式都可识别。
- Opaque `srcdoc` 使用本地键盘初始化，不改变 iframe 权限。公式打开与本地键盘验收没有外部字体请求或 MathLive 资源定位错误。

## 完整网页流程发现与修复

22106 合成服务的一次完整 UI 验收发现：手写 `r=mv/(qB)` 的 B 被自动匹配到整个名为 B 的磁场对象，生成分母 `o5` 而不是 `o5.B`；当时 GUI 校验仅调用允许暂时无解的持续定义 setter，确认后场域未定义并暂停仿真。这份 before 报告保留为实际故障证据，不能记作成功应用。

修复后，数值算术中的整个对象要求人工选择属性；唯一同名自动引用也允许显式变量绑定覆盖。原生 GUI 确认还必须在副本中实际读取当前目标的类型、量纲和数值，再写入场景。已有约束后来因输入条件变化暂时无解的保留/恢复机制仍由原生引擎处理。

实际复验在同一私有合成副本完成：原依赖 GUI→手写标准 mock job→候选图形添加下标→对照确认→返回原 GUI→选择具体物理量与单位→应用原生定义。显式选整个 B 并确认时，窗口保持打开且 scene 不变；改选 `o5.B` 后，定义 `((o3.mass * o3.speed) / (o3.charge * o5.B))` 应用至磁场宽度，原生读数为约1.5cm，场域与轨迹可见。该定义在本合成种子条件下等价于原宽度 L，仅证明本次交互/类型与依赖链；mock 答复不因此成为题意正确的模型答案。原始 seed 没有修改。
